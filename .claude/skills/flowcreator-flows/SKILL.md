# flowCreator のフローを編集する

flowCreator は「画面には短い見出しだけを出し、説明はホバー（要約）やクリック（詳細）で見せる」フローチャートエディタ。
フローは 1 件 = 1 つの JSON ファイルで保存されていて、これを直接書き換えて編集する。

## 置き場所と反映

- 保存先はプロジェクト直下の `flows/`（環境変数 `FLOWCREATOR_DATA_DIR` があればそちら）。
- ファイル名は `<フロー名>__<ID>.flow.json`。
- ユーザーがエディタ（`npm run dev`）を開いていれば、書き換えたファイルは画面に自動で反映される。ユーザーは ⌘Z で取り消せる。

## 手順

1. **把握する。** `npm run flow -- list` で一覧を出し、`npm run flow -- outline <フロー>` で構造（id・種類・見出し・線）を確認する。
   - `<フロー>` にはファイル名・ID・フロー名のどれでも使える。
   - JSON 全体を読むのは、詳細まで書き換えるときだけでよい。
2. **編集する。** JSON を直接書き換える。新しいフローは `npm run flow -- new "<フロー名>"` で作ってから書き換える。
3. **座標を付け直す。** ノードを追加したりつなぎ替えたりしたら、`npm run flow -- layout <フロー>` を実行する。
   - 座標を自分で計算しない（重なりの原因になる）。
   - ただし、ユーザーが手で配置したフローの一部だけを変える場合は layout をしない（ユーザーの配置が崩れるため）。新しいノードだけを空いている位置に置く。目安は、縦は 120px 間隔、横は 260px 間隔。
4. **検査する。** 最後に必ず `npm run flow -- validate --fix` を実行する。
   - ✗ は形式の誤りなので必ず直す。
   - △ は警告（見出しが長い、ノードが重なっている、つながっていないノードがある等）。できるだけ解消する。
   - `--fix` はファイル名をフロー名に合わせる（フロー名を変えたときに必要）。

## 書き方のルール（このアプリの考え方）

- **見出し（title）は短く。** 全角 16 字まで。画面に常に出るのはこれだけ。
- **説明は要約と詳細に分ける。**
  - 要約（summary）は 1〜2 行、全角 50 字まで。ホバーで出る。
  - それ以上の説明・担当・条件・メモ・リンクは details に入れる。クリックで出る。
- **線のラベル（label）は「Yes」「No」など全角 6 字まで。** 線の説明は detail に入れる。
- **分岐（decision）から出る線には、どの場合かが分かるラベルを付ける**（Yes / No など）。
- **開始（start）と終了（end）を置く。** 終了は複数あってもよい。
- **まとまりはグループで表す。** groups に追加し、各ノードの groupId で所属させる。
  - 1 つのノードが入れるグループは 1 つまで。入れ子にはできない。
  - メンバーのいないグループは作らない。

## 形式（schemaVersion 2）

```json
{
  "format": "flowcreator",
  "schemaVersion": 2,
  "id": "Ab3dE5fG7h",
  "title": "経費精算フロー",
  "createdAt": "2026-10-12T00:00:00.000Z",
  "updatedAt": "2026-10-12T00:00:00.000Z",
  "settings": { "direction": "TB" },
  "nodes": [
    { "id": "s", "kind": "start", "title": "申請者が立替払い", "groupId": "apply", "position": { "x": 0, "y": 0 } },
    {
      "id": "submit",
      "kind": "process",
      "title": "経費申請を提出",
      "summary": "領収書を添付して経費システムから申請する",
      "details": {
        "description": "複数行の説明。\n改行は \\n。",
        "owner": "申請者",
        "conditions": "支払日から 30 日以内",
        "notes": "メモ",
        "links": [{ "label": "経費精算規程", "url": "https://example.com/rules" }]
      },
      "groupId": "apply",
      "position": { "x": 0, "y": 120 }
    },
    { "id": "big", "kind": "decision", "title": "5万円以上？", "position": { "x": -12, "y": 240 } },
    { "id": "end", "kind": "end", "title": "振込", "position": { "x": 0, "y": 400 } }
  ],
  "edges": [
    { "id": "e1", "source": "s", "target": "submit" },
    { "id": "e2", "source": "submit", "target": "big" },
    { "id": "e3", "source": "big", "target": "end", "label": "No", "detail": "線の説明（ホバーで 1 行目、クリックで全文）" }
  ],
  "groups": [{ "id": "apply", "title": "申請", "summary": "申請者が行う作業", "description": "グループの詳しい説明" }]
}
```

フィールドごとの決まり:

- `kind` は `start` / `process` / `decision` / `end` のどれか。
- `summary`・`details` の各項目・`label`・`detail`・グループの `summary` / `description` は省略できる。空なら書かない。
- `position` はノード左上の座標（px）。y は下向きに増える。
  - ノードの大きさの目安: 処理・開始・終了は 176×44（見出しが 2 行なら 176×64）、分岐は 200×96。
- `links` の `url` は `http(s)://` か `mailto:` のみ。それ以外はリンクとして表示されない。

## ID と更新日時

- **既存の id は変えない。** エディタが選択状態や Undo の対応付けに使っている。
- **新しい id は英数字・`_`・`-` の短い文字列にする**（例: `review2`）。ノード・線・グループの間で重複させない。
- **フローの `id` は変えない。** ファイル名とエディタの対応付けに使っている。
- **書き換えたら `updatedAt` を現在時刻（ISO 8601）にする。** 一覧の並び順に使われる。
- **`format` と `schemaVersion` は変えない。**

## してはいけないこと

- `flows/` 以外にフローを書かない。
- ほかのフローのファイルを消さない。削除が必要なら、先にユーザーに確認する。
- ユーザーが頼んでいないフローを書き換えない。
