# flowCreator

初期表示を簡素に保つフローチャートエディタです。ブラウザだけで動き、サーバーは要りません。

draw.io や Mermaid では、書いた情報がすべて図の上に出るので、フローが育つほど画面が読みにくくなります。flowCreator では、図に出すのは**短い見出しだけ**です。それ以外は段階的に開きます。

| 段階 | 表示されるもの | 開き方 |
|---|---|---|
| 見出し | ノードの短い名前と形（開始・処理・分岐・終了） | 常に表示 |
| 要約 | 1〜2 行の説明 | ホバー（0.2 秒）、または拡大したときにノード内に表示 |
| 詳細 | 説明・担当・条件・メモ・リンク | クリックで右側のパネルに表示 |

- 要約か詳細があるノードには、小さな「•」だけが付きます。
- ズームの段階で表示量が変わります（L0 俯瞰: 見出しのみ / L1 標準: 見出し + 「•」 / L2 詳細: 要約もノード内に表示）。
- 分岐（菱形）の要約は、L2 で菱形の横に出します。線が横から出入りしていない側で、ほかのノードと重ならない側を選びます（どちらも使えないときだけ菱形の中）。線はこの要約の上を通らず、枠も要約を含めて囲みます。
- L2 で要約が出てノードが縦に伸びたときは、下のノードとの間が詰まらないよう、表示上の位置を段ごとに下げます。保存している位置は変えないので、標準表示に戻すと元の配置です。拡大したままドラッグやノードの追加もできます。
- 編集画面も最小限です。常時表示するのは 4 つのボタンとフロー名だけで、パネルは選択したときにしか出ません。

## 使い方

```bash
npm install
npm run dev      # http://localhost:5173
```

初めての場合は「…」→「サンプルを開く」で例を表示できます。`?` キーで操作の一覧が出ます。

**インストールせずに試す:** 公開版（GitHub Pages）は https://haruki-cl.github.io/flowCreator/ です。公開版は次の点が手元で動かす版と違います。
- フローは、そのブラウザの中（IndexedDB）にだけ保存します。サーバーやリポジトリには何も送りません。
- フォルダへの保存と、Claude Code のターミナルはありません。
- ほかのブラウザや端末からは見えないので、残したいフローは JSON で書き出してください。ほかの人に見せるときは共有リンク（下記）が手軽です。

| 操作 | 動作 |
|---|---|
| 空白をダブルクリック | ノードを追加して見出しを入力 |
| Enter / Tab | 選択中のノードの下 / 右に、つながったノードを追加（分岐からは Yes / No を自動で付ける） |
| ノードの端の丸をドラッグ | 線を引く。ノードの上で離すとつながり、空白で離すと新しいノードを作る |
| クリック | 詳細パネルを開く |
| ドラッグ | 移動。ほかのノードの上に落とすと、重ならない近くの位置へ自動でずれる。線はノードの下や枠（グループ）の名前の上を通らず、枠の縁に沿って走らないよう自動で避ける。ほかの線と同じ所を並んで通らないよう少しずらして引く |
| Shift+L | 自動整列 |
| ⌘Z / ⌘⇧Z | 元に戻す / やり直す |

### グループ（枠）

関連するノードを枠で囲んで、「申請」「承認」のようなまとまりを示せます。

- **作る:** ノードを 2 つ以上選ぶ（Shift+クリックか範囲選択）と、上に「グループにする」が出ます。⌘G でも作れます。
- **大きさ:** 枠の位置と大きさはメンバーのノードに合わせて自動で決まります。
- **入れる:** 枠の外のノードを枠の中へドラッグすると入ります。枠の中に新しいノードを置いた場合や、メンバーから Enter / Tab で追加した場合も、そのグループに入ります。
- **外す:** 枠に入っているノードは、ドラッグしても外れません（枠のほうが広がります）。外すときは、ノードをクリックしてパネルの「外す」を押すか、選んで ⌘⇧G を押します。別の枠の中へドラッグした場合は、そちらへ移ります。
- **動かす:** 枠の名前をドラッグすると、メンバーごと動きます。
- **見せ方:** 枠の名前にも要約と説明を付けられます。ホバーで要約、クリックで詳細が出ます。
- **枠を消す:** 枠を選んで Delete（または ⌘⇧G）を押すと、枠だけが消えてノードは残ります。

### 保存と共有

- **自動でファイルに保存されます。**
  - `npm run dev` で起動すると、プロジェクト直下の `flows/` に 1 フロー 1 ファイル（`<フロー名>__<ID>.flow.json`）で保存します。
  - ブラウザのデータを消しても消えません。保存先は環境変数 `FLOWCREATOR_DATA_DIR` で変えられます。
  - `flows/` は業務内容を含むことがあるので、既定では `.gitignore` に入れています。
- **保存したフローは一覧から開き直せます。** 右上の一覧ボタン（⌘O）か「…」→「保存したフロー」から開けます。一覧には保存先のフォルダも表示されます。
- **ファイルを外から書き換えると、開いている画面にそのまま反映されます。** AI などによる書き換えを想定しています。取り込んだ変更は ⌘Z で元に戻せます。
- **以前のブラウザ内のデータは、初回起動時に `flows/` へ自動でコピーします。** 元のデータは消しません。
- **API がない環境では、これまでどおりブラウザ内（IndexedDB）に保存します。** ビルドしたファイルを静的に配信した場合などです。
- 「…」→「JSON を書き出す / 読み込む」で、ファイルとして持ち出したり取り込んだりできます。
- 「…」→「閲覧用 HTML を書き出す」は、ネット接続なしで開ける 1 ファイルの HTML（約 450KB）を作ります。受け取った人も、ホバー・クリック・ズームで同じように段階的に読めます。
- 「…」→「共有リンクをコピー」で、フローの中身を入れたリンクを作れます（下記）。

#### 共有リンク

フローの中身を圧縮して URL に入れるので、リンクを送るだけで渡せます。ファイルのやり取りもサーバーも要りません。

- **開くと:** 受け取った人の画面では、公開版が開き、**編集できるコピー**として開きます。
  - そのブラウザに新しいフローとして保存され、一覧にも載ります。編集しても、作った人のフローには影響しません。
  - 開いたあとはアドレスバーからフローの中身を消すので、再読み込みしても同じフローは増えません。
  - 手元の開発サーバー（`npm run dev`）で作ったリンクも公開版を指します。
- **長さの目安:**
  - サンプル（7 ノード）で約 1,600 字、22 ノードで約 4,600 字です。説明まで書いたノードは 1 つあたり約 200 字増えます。
  - 2,000 字以下ならどこに貼っても安全です。8,000 字程度までは Slack・Teams・メールでも問題ありません。
  - 8,000 字を超えると、コピーしたときに注意を出します。貼り付け先によっては途中で切れるので、JSON か閲覧用 HTML で渡してください。途中で切れたリンクは、開いたときにエラーになります。
- **気をつけること:** リンクの中にフローの中身がそのまま入っています。
  - リンクを知っている人は誰でも中身を読めます。チャットやメールの履歴にも残ります。業務の内容を含むフローは、送り先に注意してください。
  - 中身は URL の `#` 以降に入れています。この部分はブラウザからサーバーへ送られないので、GitHub Pages 側には残りません。

### AI（Claude Code）で編集する

**エディタの中で使う。**
- 右上のターミナルボタン（⌘J）を押すと、エディタの右側に Claude Code（CLI）が開きます。フローの画面は左に縮んで見えたままです。
- 「@ このフロー」を押すと、表示中のフローのファイルが入力欄に入ります。続けて「差し戻しの分岐を追加して」のように頼めます。
- 書き換えた結果はすぐ左の画面に反映され、⌘Z で取り消せます。
- ターミナルの Claude Code は、ふだんのターミナルと同じ設定（ログイン・プラグイン・権限の設定）で動きます。開発サーバーがログインシェル経由（`$SHELL -ilc claude`）で起動しているためです。
- モデルと effort は、既定で **Sonnet・medium** にしています（フローの編集なら軽めの設定で十分なため）。ふだんの Claude Code の設定は変えていません。変えたいときは環境変数で指定します。

  ```bash
  FLOWCREATOR_CLAUDE_MODEL=opus FLOWCREATOR_CLAUDE_EFFORT=high npm run dev
  ```
- ページを再読み込みしたりパネルを閉じたりしても、会話は続いています。
- **使えるのは `npm run dev` のときだけです。** 守りとして、次の2つを入れています。
  - 自分のマシン（localhost）からの接続だけを受け付けます。
  - 起動ごとに作る合言葉（トークン）がないと接続できません。トークンはエディタの HTML にだけ入っていて、ほかのサイトからは使えません。
  - 使わないときは `FLOWCREATOR_TERMINAL=off npm run dev` で無効にできます。

**ふつうのターミナルから使う。**
- `.claude/skills/flowcreator-flows/` に Claude Code 用の Skill を用意しています。このフォルダで Claude Code を起動し、頼みごとを書くと、Skill の手順に沿って `flows/` の JSON を書き換えます。
- エディタを開いていれば、変更はすぐ画面に反映されます。

AI が使う補助コマンド（人が使ってもかまいません）:

```bash
npm run flow -- list                 # 保存してあるフローの一覧
npm run flow -- outline <フロー>     # 構造を 1 行ずつ表示（<フロー> はファイル名・ID・フロー名）
npm run flow -- layout <フロー>      # 画面の「自動整列」と同じ並べ方で座標を付け直す
npm run flow -- validate [--fix]     # 全ファイルを検査（--fix でファイル名をフロー名に合わせる）
npm run flow -- new "<フロー名>"     # 空のフローを作る
```

## 開発

```bash
npm run build    # 閲覧用テンプレート → 型チェック → エディタの順にビルド
npm run build:pages  # GitHub Pages 用（/flowCreator/ 配下・ブラウザ内保存のみ）。main に push すると Actions が公開する
npm test         # 単体テスト（Vitest）
npm run e2e      # E2E テスト（Playwright。インストール済みの Google Chrome を使う）
                 # 通常はブラウザ内保存のサーバー（:4173）、ファイル保存のテストだけ一時フォルダに保存する開発サーバー（:4174）で動かす
```

構成:

```
server/    ファイル保存の API と、Claude Code のターミナル（どちらも Vite の開発サーバーに組み込む）
scripts/   AI・コマンドライン用の補助コマンド（npm run flow）
src/
  core/      React に依存しない処理（データ形式・検証・整列・ズーム段階・HTML 書き出し・共有リンク）。単体テストはここが中心
  shared/    エディタとビューアで共用する部品（ノード、矢印、ツールチップ、ズーム段階の同期）
  editor/    エディタ（状態と Undo、キャンバス、パネル、ツールバー、自動保存、ファイル入出力）
  viewer/    閲覧用 HTML の中身（vite-plugin-singlefile で 1 ファイルにまとめる）
e2e/         Playwright のテストとフィクスチャ
```

主な技術: Vite 8 / React 19 / TypeScript 6 / React Flow（@xyflow/react 12）/ dagre / zustand / zod / idb-keyval
